## Purpose

Nyx is a code-first, fluent UI library written in Pascal. One Delphi-dialect
contract describes applications, pages, reusable components, state, themes,
layout, and interaction. The same contract produces a browser application with
pas2js and a native application with the Lazarus Component Library (LCL).

Nyx Studio is the companion Pascal application: a WYSIWYG designer and optional
split-view code workspace for multi-page applications and reusable components.
It generates Pascal beside design changes and delegates view or whole-application
compilation to a Pascal HTTP service for live-ish reload.
Studio itself is built with Nyx. Its UI and authoring controls exercise the
public library contract and its reusable components as the proof of capability.

## Decisions

| Decision | Project value |
| --- | --- |
| Pascal namespace | `nyx.*` |
| Source dialect | Delphi dialect via FPC `{$mode delphi}` and `{$H+}` |
| Primary compiler | Free Pascal; Delphi is not a supported primary compiler |
| Native target | Lazarus Component Library; exact widgetsets and minimum FPC/Lazarus versions pending toolchain validation |
| Browser target | pas2js with its matched runtime, served over HTTP |
| Owned implementation | Pascal only; no Node, npm, Python, JavaScript framework, or non-Pascal product service |
| Core model | Renderer-independent owned document tree with pages and reusable components |
| Presentation | Browser DOM/CSS adapter and LCL adapter with behavioral parity |
| Studio | Browser-first Nyx application plus Pascal HTTP compiler service; native Studio parity remains an intended outcome |
| Output configuration | Optional late target selection; machine profiles configured in Studio independently of portable designs |
| Dependencies | Standard FPC/Lazarus/pas2js facilities first; justified dependencies pinned as submodules |
| Publishing | Not yet selected |
| Work profile | Athena Lean stewardship unless explicitly changed |
| Current staffing | Solo execution, explicitly requested by the user |
| Comment/style preference | Thorough comments; blank line above if blocks |
| Public authoring | Strong Pascal types, enum choices and fluent configuration objects; generated source should feel crafted |
| Canonical records | `MILESTONES.md`, `TASKFLOW.MD`, `TODO/`, and `WORK.md` |

## Product invariants

- Application meaning lives in the shared Pascal model, never in renderer-only
  state.
- The fluent API is usable by hand and is the same contract generated by Studio.
- Generated Pascal is deterministic, readable, stable under no-op regeneration,
  and remains beside its design source.
- Default controls are accessible, themeable, responsive, visually coherent,
  and extensible through composition, subclassing where supported, properties,
  events, templates, and custom renderer adapters.
- Pages and reusable components can compile and reload independently for fast
  design work; a complete application can compile and run through the same
  service contract.
- Target selection and output tools are optional during authoring. A built Studio
  launches without application compilers; its Nyx-built output section remains
  available at any time. Readiness is checked only for the requested build.
- Editor defaults do not contain branch names or build-specific milestone text.
- Starter documents, demos and initial review examples use English. Dedicated
  qualification inputs exercise broader Unicode without restricting user text.
- Browser and LCL implementations expose the same documented semantics. Target
  differences are explicit capabilities with useful diagnostics.
- The compiler service confines inputs and outputs to admitted project/build
  roots, reports structured diagnostics, and never executes arbitrary shell
  text supplied by a client.
