**Description:**

The ordinary desktop/compact Studio authoring return exposes a named-save
failure after successful compiler-backed Pascal Apply and a visual edit. The
exact accepted companion contains a generated continuation with
`BuildNyxOriginalDocument`; the project HTTP route always chooses the literal
reader, which refuses that valid companion with “Expected BuildNyxDocument”.
The current pair and unfinished Unicode draft remain intact, but Save cannot
persist them. The desktop literal-source Save/Open/history journey passes.

Reuse the existing trusted live source checkpoint and captured-project store
contracts for named persistence. Bind any observing save to its exact workspace,
revision and complete pair. Files and HTTP input cannot supply execution proof.
Reopening persisted richer Pascal must use the existing compiler-backed project
admission, preserving the current editor until the complete replacement is
accepted. Qualify this through the same saved Workshop and ordinary controls.

This is a required prerequisite of Studio-slice criterion 3 and full-authoring
criteria 2/5. It adds no separate completion credit or waiver of their original
quality, performance, target and authoring requirements. Failure evidence and
the exact retained pair are in the external `studio-authoring-return-01` packet.

- Ordinary named Save persists the exact accepted design/Pascal/helper inventory
  and pending draft after compiled Apply and visual continuation. Use owned live
  checkpoints; untrusted serialized origin claims never bypass source admission.
  Existing literal callers retain their supported behavior.
- Missing authority, stale revision, different workspace/pair, invalid packet,
  changed disk revision and write failure refuse without overwriting a saved
  project or changing the live editor/history. Save acknowledgements identify
  the captured snapshot and preserve newer local edits.
- Ordinary Open admits the complete saved compiler-backed project before replacing
  the live pair. Preserve unfinished imported/local source through failure or
  cancellation. A successful Open is one paired undoable operation; Undo/Redo
  restore exact design, source and draft values.
- Meaningful maintained regressions cover the trust/context and storage boundaries.
  The same ordinary desktop/compact browser journey completes design/Pascal edits,
  pending-draft Save/Open, history and its own compiled runtime. Verify adjacent
  disk files and full packets independently. Check affected native consumers;
  compilation alone does not establish browser input or native interaction.
- Preserve unrelated projects, configurations and useful failure evidence. Keep
  test capture of a pre-open backup distinct from confirmed physical file writes.
  Record remaining physical/assistive, platform and performance limits explicitly.
