# NS-3_collection-action-adoption_01 — Preserve explicit setup beside automatic table actions

[North star NS-3](../../MILESTONES.md#assessment) · [Task catalog](README.md) ·
[Recovery review](NS-3_collection-recovery_01.md) ·
[Table workbench](../NS-3_control-usefulness_03.md) · [Task flow](../../TASKFLOW.MD)

**Description:**

Accepted on2026-10-30. Automatic configuration now uses a separate optional
defaults contract. The first explicit Clipboard/Export service refreshes only
that default against the current original controller; the first explicit
presenter replaces it. Private factory leases retire displaced callbacks without
revoking the shared anchor prematurely. Failed admission keeps the former owner;
post-adoption cleanup failures remain mount diagnostics instead of false admission
failures. Existing public GUIDs/vtables and duplicate explicit refusal stay intact.

Evidence in table-copy-input-01: full clipboard controls pass1499 per browser
width and1680/1669 native, including ordinary/arranged late-service recovery Copy
from an empty result. Shared ownership/refusal checks pass50 per target. Recovery
controls pass1545/1544 browser and56 per native width; the unchanged saved native
Service monitor passes25 per width. All native heaps are clean, with zero compiler
warnings. Original constructor failure, archived baseline and repaired test-seam
failures remain retained. Input and broader quality limits remain in WORK.md.

Automatic readonly recovery presentation currently occupies the same cell-action
configuration slot used by an application's explicit runtime setup. The existing
clipboard-controls consumer renders its table, configures Clipboard, then Export,
then its managed cell presenter. Export now refuses with "Export configures once
before contextual table actions" because the automatic default already installed
actions. This older valid public workflow must remain available. Changing that
consumer to a different authoring path would conceal the compatibility failure.

Keep safe automatic recovery useful while allowing the caller's first explicit
clipboard/export/presenter configuration to take precedence through the public
specialized contracts. Defaults must not become a hidden one-shot configuration
by the caller. Preserve the existing refusal of duplicate explicit setup, exact
host authority and inert journal ownership. This is original recovery/workbench
compatibility scope, with no separate completion percentage or credit.

Starting failure: the maintained browser clipboard regression stops after two
checks during its unchanged constructor, before any Copy input is dispatched.
Receipts are in table-copy-input-01. Recovery review is reopened until this
regression and the scoped recovery criteria are requalified. The browser Copy
bridge itself has exact same-application real-host evidence at both widths; full
acceptance remains pending this prerequisite.

**Acceptance Criteria:**

- The original runtime sequence Render, ConfigureClipboard, ConfigureExport,
  ConfigureCellActions succeeds on ordinary and arranged browser/LCL tables with
  automatic recovery defaults. Do not reorder/weaken the maintained legacy
  constructor, add DOM/LCL workarounds or require an authored workbench policy.
- Default recovery remains reachable, including an empty filtered result, and
  uses the proper current explicit host/policy when supplied. Explicit presenter
  setup takes precedence once; a second explicit configuration still refuses.
  Default adoption does not grant new clipboard/file/network authority.
- Candidate admission remains atomic. Invalid/failed explicit setup cannot lose
  an existing useful default, journal, live draft/caret, selection or accepted
  source. Successful adoption retires only the displaced default's UI/request
  resources; immutable recovery entries and independent peer tables stay valid.
- Ownership is acyclic and original input/scheduler fences remain authoritative.
  Old callbacks cannot reach the replacement presenter. Preserve public interface
  compatibility and alternative mounts' honest optional support.
- Retain the original failed regression, then pass that consumer and appropriate
  recovery/own-application checks on both targets at wide/compact widths, with
  clean native heaps and explicit input limits. Preserve exact saved pairs/history,
  output/clipboard state, unrelated projects and fixed listeners. Restore recovery
  acceptance only after its unchanged criteria and this regression are satisfied.

**Blockers**

- None for implementation. Existing scoped presenters, explicit services, journal
  and input-lifetime infrastructure provide the required boundaries.
