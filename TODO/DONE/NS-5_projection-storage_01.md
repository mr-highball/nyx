# NS-5_projection-storage_01 — Owned constructor artifact storage

[North stars](../../MILESTONES.md) · [Task catalog](../README.md) ·
[Current work](../../WORK.md) · [Task flow](../../TASKFLOW.MD)

**Description:**

Make repeated compiler-executed view construction practical on the development
host without accumulating an entire native compiler output tree per edit.
The accepted source-projection API returns a detached native design/report and
no native executable artifact. Its current executor nevertheless retains all
intermediates. During the semantic transaction packet the drive filled, and a
bounded cleanup of inactive binaries recovered space while leaving units intact.

This independently useful prerequisite owns storage for newly allocated source
projection invocations. Native verification should retain its sources/results/
diagnostics and retire only its own unchanged compiler derivatives after process
join. A typed trusted-host policy can preserve all files. Compiled browser worker
packages remain usable. Capacity admission should report pressure before another
large native invocation, independently of output selection and document editing.

This does not authorize a sweep of existing job/runtime directories or protected
projects, nor accept application artifact caching, all-platform CI/delivery,
browser execution or visual parity. The original service/reload and delivery
acceptance remains unchanged. Owner: NS-5; credit pending accepted evidence.

**Acceptance Criteria:**

- Fresh invocation scope is explicit and exclusive. Retention never adopts an
  existing directory, follows a reparse/symbolic link or visits another job,
  source tree, project or active output. Compiler derivatives are captured after
  compiler join and unchanged identity/content is checked before retirement.
  Constructor/process-family join precedes file retirement. Unexpected, moved,
  changed or locked files produce a bounded deferred result, without a false
  complete report or document mutation. Retained source/result/log evidence stays
  exact through success, failure and cancellation.
- Native policy and capacity choices use strong Pascal types, with documented
  defaults, ownership and failure behavior. Callers can retain all files or tune
  capacity admission. Unknown choices refuse before allocation. Pressure returns
  useful typed failure while authoring and existing projects remain available.
- Actual native compiler/constructor and owning-worker consumers retain exact
  executed meaning and diagnostics after retirement. The same host's actual
  pas2js compilation retains its complete readable worker package. Qualification
  identifies the host/compiler/platform, does not infer browser execution or
  untested OS support, and includes zero-leak lifetime/refusal evidence.
- The maintained Pascal qualification is integrated with repeatable build
  orchestration and documents the evidence boundary and remaining platform,
  application-cache and observing rollout requirements.

**Blockers**

- [Compiler-executed source projection](NS-1_source-projection_01.md), accepted.
