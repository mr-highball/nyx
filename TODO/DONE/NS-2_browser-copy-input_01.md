**Description:**

Accepted on2026-10-30. The optional target facet and renderer Copy listener route
the exact focused data cell or captured range through the original controller,
canonical clipboard stages and configured host. It invents no key/Click event or
event clipboard-data write. Active-editor/custom-child/default-claimed input

Evidence and source identities are in table-copy-input-01 and WORK.md.

The same saved/generated Service monitor handles a correctly produced copy key,
but the browser automation's Copy action produces a Clipboard Copy event without
keydown. The passive Pascal observer records one Copy event and no host entry.
The renderer/table currently has no Copy-event input bridge. The earlier apparent
shortcut failure is therefore a real semantic-input gap, rather than proof that
the existing key command or clipboard host is broken. Browser menu/semantic Copy
must reach the same portable command without inventing a keyboard event.

Add the target bridge using existing original-input reservation, cell/range
capture, canonical clipboard cancellation and the single host request slot.
Preserve explicit host authority and native editor behavior. Do not write directly
to event clipboard data to bypass the configured host, manufacture a key callback,
or add another copy engine. This is a scoped prerequisite of the original table
workbench/parity outcomes, with no separate completion percentage or credit.
Starting receipts are in table-keyboard-return-01; [WORK](../../WORK.md) retains the
input distinction, exact generated source and earlier successful typed-key path.

**Acceptance Criteria:**

- Standard Copy input from an actual focused ordinary table data cell uses its
  exact accepted RAW value or explicitly enabled original range, with existing
  header/line-ending/field policies. The same saved browser application copies
  its intended rectangle through the real configured host at both widths.
- Reuse the original controller and single request slot. Canonical clipboard
  callbacks, cancellation, scheduler rules, captured revisions and original input
  admission remain authoritative. Do not manufacture keyboard/Click callbacks.
  A normal key path followed by browser default handling cannot write twice.
- Active editors, text selections, custom interactive descendants, composition,
  disabled/busy/retired mounts and events claimed by earlier handlers keep their
  correct behavior. Claim browser defaults only for an admitted original data
  command; do not retarget document-wide Copy to a different control.
- Changes to source, query/page, columns, selection or input incarnation refuse
  stale commands without borrowing newer row/field identities. Ownership stays
  acyclic; callbacks cannot touch retired/replacement targets. Existing specialized
  interface implementations remain compatible through an optional target facet.
- Retain the meaningful before-failure and qualify actual semantic Copy, typed-key
  coexistence, exact real clipboard effects and unchanged native consumers. State
  raw/synthetic/widget/hardware limits honestly. Preserve exact saved pairs/history,
  original clipboard/output settings, unrelated projects and both fixed listeners.
