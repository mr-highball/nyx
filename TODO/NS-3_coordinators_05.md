# NS-3_coordinators_05 — Reuse creator behavior in reusable and embedded views

[North stars](../MILESTONES.md) · [Task catalog](README.md) · [Task flow](../TASKFLOW.MD)

**Description:**

Make an independently registered creator behavior work inside ordinary reusable
instances and embedded content alongside migrated built-ins. An ordinary root
Selection Summary alone does not prove scoped part resolution, independent
stores or replacement of an embedded owner. Deliver an application demonstrating
those outcomes through the existing common coordinator path.

Owner: [common coordinators](NS-3_coordinators_01.md), original criterion5 and
shared criteria1–3, serving [components](NS-3_components_01.md) criteria1/3 and
[Studio authoring](NS-4_studio-authoring_01.md). This split adds no credit.
DataToolbar remains downstream; it is not a reverse prerequisite for this work.

**Work packets and handoff:**

| Packet | Reviewable outcome | Dependency and evidence |
| --- | --- | --- |
| R1 — Reusable application | Two real reusable creator instances with nested roles, independent stores/claims and exact specialized lookup coexist with migrated built-ins | Accepted registration/MasterDetail and qualified Kanban; root owns host propagation, helper owns the separately released ordinary creator consumer. Real input must leave definitions and siblings intact. |
| R2 — Embedded application | Existing SetupCanvas/content mounts inherit a fixed caller snapshot; explicit caller override, including empty caller membership, has a documented policy; automatic built-ins compose separately | R1. Every child retains its own future event generation and weak refresh. Failed/same-ID replacement and disposal preserve the accepted owner and revoke old commands. |
| R3 — Both-host acceptance | The same useful reusable/embedded application executes native and admitted-browser input/lifetime cases | R1/R2. Native clean heaps and matching browser compiles are intermediate evidence; actual browser execution is still required by criterion5. |

Root reviews registry inheritance/override and child lifetime before either source
scope is released. Common candidate traversal already covers expanded reusable
nodes under one snapshot; embedded SetupCanvas is the concrete propagation gap,
not a reason for a second
registry or event engine. Finish R1 before R2 and retain actual refusal results.
The missing admitted browser session is R3's explicit external gate. Compilation
cannot close05, parent01 or their downstream acceptance. No task credit is added.

**Acceptance Criteria:**

- The creator example runs in at least two ordinary reusable instances and
  independently owned embedded content on both application hosts. Real input
  changes the intended instance only. Definitions, siblings, data/defaults and
  authored source remain intact; no renderer-specific creator branch is added.
- Typed roles resolve within the exact realized owner, including nested named
  parts. Missing, ambiguous, foreign or incompatible roles refuse before mount.
  Saved intent cannot manufacture executable factories or host/service authority.
- Creator and built-in coordinators coexist in one accepted candidate without
  duplicate observers or competing text ownership. Specialized binding interfaces
  survive generic lookup. Nested reusable/embedded registry inheritance and
  explicit overrides have a documented deterministic policy. Each candidate
  captures the correct snapshot; replacements affect future candidates only.
- Embedded replacement, same-ID successor, navigation and disposal revoke the
  former generation before controls retire. A failed candidate preserves the
  prior usable view; abandoned candidates release only their own resources.
  Reentrant validation and notification-triggered disposal do not retain hosts
  or permit stale refresh, projection or collection commands.
- Useful behavior, refusal and independent lifetimes execute natively with
  clean heaps and in an admitted browser session. Compile-only browser evidence
  remains explicitly incomplete. Applicable existing root/embedded routes and
  built-in compatibility retain their contracts. Publish the creator usage and
  exact supported boundaries with the ordinary application example.

**Blockers**

- [Caller-owned registration](DONE/NS-3_coordinators_02.md) supplies the extension API
  and first independently useful root application.
- [MasterDetail migration](DONE/NS-3_coordinators_03.md) and
  [Kanban migration](NS-3_coordinators_04.md) supply the built-in owners used by
  the mixed/reusable acceptance above. Their native evidence alone does not
  satisfy this task's browser requirement.
- External: browser execution/observing needs an admitted host/session. Until
  supplied, preserve this gate as open; no host/config retry, server restart,
  new MCP/tool/wire rollout or extra agent is authorized by this task.
