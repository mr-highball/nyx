# NS-4_interact-flows_01 — Safely mount root declarative flows in Interact

[North stars](../MILESTONES.md) · [Task catalog](README.md) · [Task flow](../TASKFLOW.MD)

**Description:**

Make ordinary root declarative event flows run in Studio's Interact preview,
using the same admitted document, application stores and generation as its
rendered controls. Owner: NS-4, serving [Studio authoring](NS-4_studio-authoring_01.md)
and [Edit data discovery](NS-4_master-detail-events_01.md). Completion credit
remains with those original outcomes; this prerequisite adds no credit.

Actual starting evidence: the completion-aware MasterDetail Studio consumer
reaches visible Inspector, ordinary route mapping and paired Apply/Undo/Redo at
1280 and390. Both runs receive exactly one copied Edit callback, but the bound
Memo keeps its initial text until the60-second deadline; both have clean heaps.
`TNyxStudioPreviewRuntime` owns stores/context only. Both `RenderStudioCanvas`
methods pass that context to `RenderContext`, whose root routes remain host-owned.
Ordinary application hosts bind them separately. Changing wait durations or
dropping the preview assertion would leave this product gap intact.

Reuse existing staged route collection, prospective event observations and
publication/readiness owners. Root Pascal callback implementations still require
their compiled host. Project metadata must not manufacture executable creators,
HTTP/file/dialog services, compiler access or other host authority.

  page/reusable context. Preparation validates complete routes and scheduler
  policies without resolving executable creators or observing live input. The
  new route observations use the renderer's same prospective event view and
  generation, including route-only pages and Interact/design transitions.
- One optional typed root-publication seam joins existing renderer admission.
  Hidden Build/Sync and all outward validators happen before final local
  readiness fences. Failure leaves the old controls, stores, event observations
  and runtime usable; abandoned preparations retire only their own reservations.
  No fake empty document or stripping authored routes is used for admission.
- Install adopts preallocated route/context/runtime ownership without callouts
  or allocation. New bindings remain dormant before installation; the old
  generation is revoked before its controls retire. Implicit remount/Sync keeps
  the admitted root preparation source rather than silently losing its flows.
- Postcommit notification/cleanup failure reports committed adoption. The host
  already owns the accepted runtime even if `RenderContext` raises afterward;
  its new controls never borrow freed stores. Retirement attempts all displaced
  cleanup. Navigation/disposal cancels queued results without retaining hosts.
- The existing ordinary MasterDetail consumer stays completion-aware and keeps
  all assertions: move selection before yielding; copied callback and formatted
  JSON still describe the original record; visible Memo, defaults, reusable
  isolation, one-step history, Save/Open and exact generated application work.
  Native1280/390 evidence has clean heaps. Matching browser consumers retain
  their async lifetime assertions; compile-only evidence is explicitly limited.
- Existing root/embedded flow routing, callbacks, Kanban/MasterDetail mounts and
  event observation ordering remain compatible. Focused refusal, reentrant
