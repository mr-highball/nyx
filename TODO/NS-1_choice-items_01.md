# NS-1_choice-items_01 — Typed choice keys and human captions

[Milestones](../MILESTONES.md) · [Task catalog](README.md) · [Task flow](../TASKFLOW.MD)

**Description:**

The Logic toolbox has creator descriptions, intent groups and tag search, but its
operation selector shows internal kind names because ordinary Nyx selects use one
string for both display and stored value. Add one portable typed choice contract
and consume it in the existing Logic editor. Stable keys must never depend on
translated captions, duplicate labels or physical indexes. NS-1 owns the contract;
NS-2 adapters and NS-4 authoring consume it. This is a prerequisite of the Logic
toolbox workflow, with no separate completion weight or percentage assigned.
Existing newline Items and existing select projects remain compatible. This task
does not replace collection-backed lists, introduce executable creator authority
or claim all radio/segmented controls have the new capability.

Criterion1 is accepted on2026-11-01 from native/browser choice data29 and model31,
including bounded refusal, immutable branches, exact Unicode and normalized
foreign-provider ownership/reentrancy. Source18, creator/resource authoring19 and
actual handwritten/generated selects qualify further work: native18/browser15
per desktop/compact allocation, with clean native heaps. Ordinary Studio passes
native97/99 and browser76 at desktop width; compact browser project-menu opening
still fails at stage20. WORK owns exact evidence and retained failures. No whole
task or percentage closes. Full Inspector/MCP choice editing, event/focus/visual
coverage, public facade literal replay and executed-companion customization
remain. Complete the linked compact menu return before the full authoring claim.

**Acceptance Criteria:**

- Reference-counted immutable choice collections, typed open key references and
  fluent builders preserve exact Unicode keys/captions, explicit empty keys and
  immutable branches. Duplicate keys, malformed data and exceeded budgets refuse
  atomically; duplicate captions remain valid and unambiguous.
- Built-in select authoring uses typed configuration. Clone, persistence,
  source projection, crafted Pascal and compiled companions preserve optional
  choices beside unchanged legacy Items. Unknown old extension data must not be
  silently reinterpreted as typed choices. Source admission remains honest.
- Browser/LCL controls display captions but publish exact keys through ordinary
  input, callbacks and state bindings. Programmatic values and caption/order-only
  updates preserve selection, focus and event semantics; unknown keys do not
  invent a first value. Invalid updates preserve the accepted model and control.
- Ordinary Studio and bounded MCP inspection/editing expose the key/caption data
  through existing revision-aware commands, paired history and deliberate saving.
  Malformed input or unfinished drafts preserve the accepted pair.
- Logic discovery/configuration uses friendly operation titles with stable kind
  keys, accessible action names and explicit selection feedback. Built-in and
  creator operations remain searchable/groupable without executable authority.
- Actual native/browser desktop/compact journeys, Unicode and duplicate-caption
  cases, history and execution of their own generated application qualify the
  intended result. Compilation, widget input, visual inspection and broader
  accessibility/performance remain distinguished.
