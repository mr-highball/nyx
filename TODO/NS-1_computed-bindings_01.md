# NS-1_computed-bindings_01 — Typed computed bindings

[North stars](../MILESTONES.md) · [Task catalog](README.md) · [Task flow](../TASKFLOW.MD)

**Description:**

The user explicitly requested computed bindings on 2026-10-13 after reviewing
Nyx's expression capabilities. Existing bindings directly project one typed
state/resource value. Extend that same public binding contract with immutable,
strongly typed expressions for composed captions, arithmetic and conditions over
multiple state values. This is an additive outcome beyond the accepted direct
scalar-state foundation, not a reopening of its historical evidence. NS-1 owns
the portable contract; source, Studio, runtime parity and delivery consume it.
No completion credit is allocated from a proposal or isolated evaluator.
The existing [source](NS-1_codegen_01.md),
[authoring](NS-4_studio-authoring_01.md),
[workflow](NS-4_agent-workflows_01.md) and
[parity](NS-2_parity-accessibility_01.md) owners consume this new evidence while
retaining their complete product criteria.

**Acceptance Criteria:**

- Specialized reference-counted Boolean, text, Integer and number expression
  interfaces expose fluent typed literals/references, Boolean composition,
  comparisons, checked arithmetic, text composition and conditional branches.
  Incompatible expression families fail Pascal typing. Open names use existing
  distinct state references; closed choices use enums. Arbitrary strings never
  become executable code or behavior selectors.
- Independently owned expression trees have bounded strict versioned descriptors,
  exact Unicode/numeric persistence and deterministic readable generated Pascal.
  Shared source admission and real FPC/pas2js compilation reconstruct their meaning;
  derived recipes, reusable overrides, project transfer and paired history retain
  independence. Alternate interface implementations enter through admitted copies.
- Direct bindings and computed bindings share atomic candidate admission. Missing
  keys, wrong kinds, overflow, nonfinite results, invalid division, incompatible
  control targets and malformed trees refuse without changing accepted state/UI.
  Computed bindings are read-only projections; two-way editing retains explicit
  direct-state ownership. Conditions preserve defined lazy-branch behavior while
  dependency/type validation remains complete.
- Actual browser and LCL applications update calculated captions/metrics and
  enabled/visible conditions from multiple state values, retaining input drafts,
  control identity, navigation and independent runtime stores. Owned snapshots
  support safe evaluation away from UI; scheduler-mediated publication retains
  the same guards. Store-only/evaluator-only fixtures do not establish integration.
- Studio uses public Nyx expression authoring controls and bounded semantic tools
  to inspect, create/change and remove computed bindings as ordinary undoable
  design/Pascal operations. Pending drafts, stale revisions and invalid proposals
  preserve current work. English demos exercise practical conditions, calculations
  and composed captions, with selective desktop/narrow previews.
- Document evaluation costs/dependency discovery and measure representative
  updates without unsupported incremental/performance claims. Preserve direct
  bindings, portable text/domain rules and existing project compatibility. Qualify
  an observing release separately from current-source implementation.
